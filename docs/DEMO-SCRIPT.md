# Five-minute demonstration (maximum 5:00)

Practice once before recording; use only synthetic photos and fictional residents. This script is a recording plan, not a claim that a video has been recorded. Keep the persistent mode banner in frame. Start with `npm run dev` and a new local workspace; never imply that deterministic output is Bedrock execution. If an AWS run is available, separately show component status and actual sanitized Strands tool activity.

**0:00–0:25 — The problem and who it serves.** “A broken curb ramp can make an everyday trip difficult for someone using a wheelchair or pushing a stroller. Reporting it is only the beginning. Neighborhood Fixer helps neighbors share evidence, send one approved request, and check whether the repair actually happened.” Show Neighborhood with the seeded nearby pothole. “This is a local demo with simulated AI and a fictional agency.”

**0:25–1:15 — Alex reports.** Choose Report an issue. Use the clearly labeled illustrative curb-before photo. Description: “The concrete edge of the curb ramp is broken beside the yellow tactile surface. I found it difficult to move a stroller across the transition.” Select Sidewalks & curb ramps. Confirm Maple Street & Alder Avenue at the seeded demo coordinates. Confirm public walkway knowledge only for this fictional fixture. Show analysis: resident claims are separate from visible facts; width, ownership records, and severity remain unknown. No exact measurements are inferred. Select Different issue when only the nearby pothole exists. Show prepared report, route source and date. Save for later; do not approve yet.

**1:15–1:55 — Sam contributes.** In local demo controls switch to Sam in the same isolated workspace. Report the same ramp with the before fixture and a second description. Confirm the location. Select Add my observation on the ramp candidate. Show two observations and one canonical incident. Point out that the nearby pothole remains a different case and no second submission is started.

**1:55–2:55 — Alex approves one exact report.** Switch back to Alex. On case detail review the recipient, fields, contact (empty unless explicitly entered), selected attachments, and immutable report revision. Decide publication separately. Approve the exact report. Show persisted events, actual browser steps, receipt ID, and redacted browser screenshot when retained. Open the real fictional receipt page. “The executor submits the frozen approved payload. It cannot choose another destination.”

**2:55–3:40 — Closed is not fixed.** Use protected local scenario controls to set the fictional ticket to Closed, with note “duplicate.” Advance the local virtual clock so the persisted status-check job becomes due. Show agency Closed and independent Resolution Unverified/Verification requested. “An agency saying closed does not prove the ramp was repaired.” Choose Looks fixed with the synthetic after-photo; show Resident-confirmed fixed, never Certified safe. Switch to Sam to show the same outcome and notification.

**3:40–4:25 — Failure without a duplicate ticket.** For a separate fictional case, enable Lost receipt in local controls, prepare and approve, then show OUTCOME_UNKNOWN. Reconcile the receipt for the same attempt. Show one ticket and no blind re-submit. Keep this case pre-prepared if needed to stay within five minutes; disclose any cut or time jump.

**4:25–4:50 — Ambiguous route.** Show a prepared example with public ownership unknown or outside the fictional boundary. The application asks for missing information or provides an assisted handoff packet. No invented Seattle/Redmond integration and no automatic external report.

**4:50–5:00 — Architecture and limits.** Show the Mermaid architecture. “The local journey is reproducible. Real Strands/Bedrock and AWS deployment code are included; cloud deployment and model evidence are labeled separately in the test report. Real municipal submissions remain disabled.”
